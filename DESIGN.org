* 状态与核心决策

这份文档只记录我确定的一些决策，剩下的技术决策都可能是之后改变的，现在主要是让AI快速出MVP。

本项目让 Org 文档中的数学内容使用 Typst math syntax，并接入 Org 编辑、预览与导出工作流。
接入会改变ox-typst（如果你安装了），ox-html，ox-latex，

直接采用ox-typst提供的  =TYPST_HEADER= 作为preamble语法，它会改变数学宏。

采用 Emacs Lisp frontend + 常驻 Rust subprocess。Elisp 管理 Org 结构与用户交互，Rust
复用现有库完成转换。


| 路径         | 职责                         | 默认实现方向                         |
|--------------+------------------------------+--------------------------------------|
| 编辑与识别   | Org 数学区域、位置和生命周期 | buffer-local minor mode + Org adapter |
| Preview      | Typst → SVG                  | 官方 Typst 编译与 SVG crates          |
| HTML export  | Typst → MathML               | 官方 HTML 编译路径                   |
| LaTeX export | Typst → LaTeX                | 可插拔 Rust backend，优先评估 tylax   |
| 通信         | 异步请求、批量转换、诊断     | stdio JSON-RPC 2.0                    |

最低支持已实测的 Emacs 30.2 和 Org 9.7.11，不引入旧版兼容层；开发环境继续使用 Emacs 31。

第一版包含：显式启用的 Typst 数学语义、行内及独立公式、派生 HTML/
typst/latex exporter。

SVG preview 内置在 org-typst-math 包中，代码分文件，通过 org-typst-preview 命令调用。源码高亮留作后续功能。

不要做太多的防护，我们永远默认用户在数学界内输入的都是正常的数学符号和定义好的宏，

* 用户模型与源语法
** 显式启用与覆盖范围

建议文件声明 =#+TYPST_MATH: t= ，提供 =org-typst-math-mode= 。
文件声明供导出识别，minor mode 控制当前 buffer 的编辑与预览。导出仍以文件声明及显式导出选项为准。

启用后，受支持数学分隔符内的内容一律解释为 Typst。

Org 容器，Typst 数学正文

采用和 Org 完全一样的数学容器：=$...$=、=\(...\)= 为行内；=$$...$$=、=\[...\]= 为独立公式。
只不过剥除容器后，内部内容以 Typst math mode 解析。


#+begin_example
#+TYPST_MATH: t

行内公式 $alpha + beta = gamma$，或者 \(frac(a, b)\)。

\[
sum_(k=1)^n k = (n(n+1))/2
\]
#+end_example

这覆盖的是数学正文的语言，不宣称 Org 原生接受完整 Typst delimiter grammar。
尤其 =$ x^2 $= ；。Org 对 dollar 边界及换行的限制仍有效。


补全和源码编辑模式为后续功能。

* 源码显示：org-pretty-entities

已实现。=org-pretty-entities= 非 nil 且 =org-typst-math-mode= 启用时，
数学片段内 =org-typst-math-entities= 列出的 Typst 标识符用 Unicode 显示。
默认含希腊字母和 integral、sum、dif、compose、dot、eq.not、tack.r、
in、forall、exists、times 等常用算子，
其他符号由用户在该 alist 中添加。标识符可含 =.=，以支持 =eq.not=、
=tack.r= 这类带变体的符号名。

实现挂在 =org-font-lock-set-keywords-hook= 上，追加一个只处理数学片段的
font-lock matcher；片段判定复用 =org-typst-math-fragment=。显示只改 composition，
不改源码、预览与导出。关闭 mode 时 decompose 并重新 fontify，恢复
=org-fontify-entities= 自己的 composition。

* 通用 special block 导出

块名到 Typst 函数调用、块头参数解析、标签及引用处理均归 ox-typst。
实现位于 [[https://github.com/DzmingLi/ox-typst][ox-typst fork]]，尚未合入上游。
org-typst-math 的 Typst 派生后端仅覆盖数学片段，继承 ox-typst 的块和链接导出。
普通块无需 TYPST_MATH 开关；HTML、LaTeX 使用 Org 原生导出逻辑。

* 内置 SVG 预览

Rust helper 的 math/convert 新增 svg target，通过官方 typst-layout 与 typst-svg
直接生成透明 SVG，复用字体库与编译缓存。批量请求通过现有 typst-client 异步入口发送，
不启动 Typst CLI。每个公式的前景色随请求传入，大小通过 Emacs image scale 调整。

org-typst-math-preview.el 随核心包安装，提供 org-typst-preview
及手动 refresh、clear、diagnostics 命令，无需额外的预览 mode；编辑后 overlay 失效。
未完成的请求合并后续刷新意图；buffer 修改 tick 与 generation 防止过期结果覆盖源码。
清除预览或禁用适配时使未返回请求失效，关闭 buffer 时清理 overlay。

第一版预览数学片段，读取当前 buffer 的 TYPST_HEADER；定理块整体预览、浮窗和
可见区域调度不在本次实现中。公式诊断沿用现有位置映射，但自动刷新不弹出错误窗口。

** org-fragtog-plus

独立仓库提供 org-fragtog-plus 包，支持 Emacs 30.2+，不依赖或 advice 原 org-fragtog。
它负责光标检测、空闲延迟、片段跟踪和生命周期清理；backend 负责 fragment/show/hide/clear。
默认 backend 调用 Org 内置 LaTeX 预览，Typst adapter 位于 org-typst-math-preview.el。
org-typst-math-mode 启用时选择 buffer-local Typst backend，关闭时恢复 LaTeX。
backend 切换、mode 关闭和 buffer 关闭时取消定时器并清理对应预览。
手动 org-typst-preview 不需要开启自动切换 mode，前缀参数清除预览。
