#+TITLE: org-typst-math
#+OPTIONS: toc:nil

在 Org 数学容器内使用 Typst 数学语法，通过常驻 Rust helper 导出 MathML 或 LaTeX，或交给
社区 ox-typst 导出整份 Typst 文档。支持 Emacs 30.2+ 和 Org 9.7.11+，不引入旧版兼容层。

* 安装

#+begin_src sh
git clone https://github.com/DzmingLi/org-typst-math.git
cd org-typst-math
nix profile install .
nix develop --command python3 scripts/package.py
#+end_src

=Nix profile= 安装 Rust helper；Elisp 包通过下文的 =package-install-file= 安装。
helper 位于 PATH 时无需设置 =typst-client-command=。
也可用 =nix build= 构建 helper，或在开发 shell 中执行 =cargo build=。

* 开发环境与运行

项目环境由 =flake.nix= 提供，版本固定在 =flake.lock=。其中包含 Rust 工具链、Emacs 31、
Org、ox-typst 和 Typst CLI；LaTeX PDF 导出需自行安装 TeX。helper 本身直接链接 Typst Rust 库，不调用 CLI。


在示例 buffer 中使用普通 Org 导出菜单：=C-c C-e h h= 导出 HTML，=C-c C-e y f= 导出
Typst，=C-c C-e l l= 导出 LaTeX，=C-c C-e l p= 经 LaTeX 编译为 PDF，=C-c C-e y p= 经 ox-typst 编译为 PDF。只有带 =TYPST_MATH: t= 声明的文档才会
自动选择本包的派生 exporter；其他文档保持原行为。

开发 shell 将当前项目的 =target/debug= 加入 PATH。在已有 Emacs 会话里手动加载时：

#+begin_src emacs-lisp
(add-to-list 'load-path (expand-file-name "~/src/org-typst-math/lisp"))
(setq typst-client-command
      (list (expand-file-name "~/src/org-typst-math/target/debug/org-typst-math-helper")))
(require 'org-typst-math)
(require 'ox-typst nil t)  ; 可选，仅整份 Typst/PDF 导出需要
#+end_src

无需为了 HTML 导出安装 Typst CLI 或 ox-typst。只需已编译的 helper 和这两个 Elisp 包。
后续可用 =cargo build --release= 构建优化后的 helper，并调整 =typst-client-command=。

* 文档语法

#+begin_example
#+TYPST_MATH: t
#+TYPST_HEADER: #let vect(x) = math.bold(x)
#+TYPST_HEADER: #import "math-defs.typ": *

行内 $vect(v)$，或者 \(frac(a, b)\)。

\[
sum_(k=1)^n k = (n(n+1))/2
\]
#+end_example

删去示例中不需要的 import，或提供相应文件。多个 =TYPST_HEADER= 按顺序拼接。
本地 import 相对于 Org 文档目录解析；每次 HTML/LaTeX 导出会重新读取依赖。
=$...$= 和 =\(...\)= 为行内，=$$...$$= 和 =\[...\]= 为独立公式。
识别范围完全沿用 Org，源代码块和原样文本不会被扫描为数学。

=org-typst-math-mode= 是编辑端开关，不修改文件；导出以文件声明或
=org-export-as= 的 =:typst-math t= 选项为准。直接选择 =typst-math-html= 或
=typst-math-latex= 或 =typst-math-typst= 后端也可以明确启用。派生 Typst 后端须先加载 ox-typst。

* 包与进程

| 包                    | 文件                                                     | 依赖           |
|-----------------------+----------------------------------------------------------+----------------|
| typst-client          | lisp/typst-client.el                                     | Emacs jsonrpc  |
| org-typst-math         | lisp/org-typst-math.el、lisp/org-typst-math-export.el      | typst-client、Org |
| org-fragtog-plus      | lisp/org-fragtog-plus.el                                | Org，Emacs 30.2+ |
| 内置预览模块          | lisp/org-typst-math-preview.el                           | 随核心包安装   |

也可生成三个独立的安装包（org-fragtog-plus 为可选包）：

#+begin_src sh
python3 scripts/package.py
#+end_src

在 Emacs 中用 =M-x package-install-file= 依次安装 =work/packages/= 内的
=typst-client-0.1.0.tar= 和 =org-typst-math-0.1.0.tar=，再配置 helper 路径并
=(require 'org-typst-math)=。自动切换另安装 =org-fragtog-plus-0.1.0.tar=。Rust helper 单独构建，不包含在 Elisp archive 中。

两个现有包的包管理器文件选择应分别为
=lisp/typst-client.el= 与 =lisp/org-typst-math*.el=；export 和 preview 文件都属于核心包的内部模块。

客户端按文档目录复用连接。每次 HTML/LaTeX 导出收集全部数学片段，发出一次批量 JSON-RPC 请求。
Rust 保留字体库和 Typst 编译缓存；没有磁盘结果缓存或每公式进程。
Typst 导出只传递数学源码与 header，不需要 helper。=M-x typst-client-stop= 关闭已有进程，
后续请求自动重启。客户端也提供异步转换入口，供内置预览使用。


* 数学环境与自定义块

用 =M-x customize-variable RET org-typst-math-block-alist= 配置别名，或：

#+begin_src emacs-lisp
(setq org-typst-math-block-alist
      '(("typst-theorem" . "theorem")
        ("typst-example" . "example")
        ("typst-proof" . "proof")))
#+end_src

默认表为空；只有配置的 special block 参与转换。可映射任意自定义环境名。
没有自动前缀规则，普通 =begin_example= 仍是原样文本块。

#+begin_example
#+NAME: my-theorem
#+ATTR_TYPST: :title [A theorem] :numbering none
#+ATTR_LATEX: :options [A theorem]
#+begin_typst-theorem
For real $x$, $x^2 >= 0$.
#+end_typst-theorem

See [[my-theorem][the theorem]].
#+end_example

Typst 生成 =#theorem(title: [A theorem], numbering: none)[...]=。
=:positional= 传位置参数，其余键原名传递；参数值是原始 Typst 表达式，
例如 =:name "Title"=、=:positional [Title]=、=:outlined false=、=:fill rgb("#fff")=。
可重复写位置参数或分多行 ATTR_TYPST。NAME 默认生成与 Org 链接一致的后置标签；
需要标签参数时写 =:label <thm:one>=，保留 NAME 作为 Org 链接目标。

LaTeX 使用映射后的环境名和 ATTR_LATEX，HTML 使用映射后的 class 和 ATTR_HTML。
Typst 的任意参数不会转成 HTML 或 LaTeX 参数；HTML 不自动生成定理编号。

完整示例见 [[file:examples/blocks.org][blocks.org]]，其中 theorion 初始化放在文首
=begin_export typst= 中，只用于整份 Typst 文档，不进入数学 helper。
使用上面的别名配置后，可按普通 Org 菜单导出这份示例。数学宏仍放在 TYPST_HEADER。



* 内置公式预览与 org-fragtog-plus

预览随 org-typst-math 安装，与导出共用常驻 helper。需要带 SVG 支持的图形 Emacs 30.2+。

- =M-x org-typst-preview=：异步批量预览当前 buffer；带前缀参数时清除预览。
- =M-x org-typst-math-preview-refresh=、=org-typst-math-preview-clear=：显式刷新、清除。
- =M-x org-typst-math-preview-diagnostics=：查看错误位置。

org-fragtog-plus 是独立可选包，默认使用 Org 内置 LaTeX 预览。
启用 org-typst-math-mode 时自动选择 buffer-local Typst backend，关闭时恢复 LaTeX。
没有对原 org-fragtog 的 advice，也不依赖原包；同一 buffer 不要同时启用两个切换 mode。

#+begin_src emacs-lisp
(require 'org-typst-math)
(require 'org-fragtog-plus)
;; 在需要 Typst 数学预览的 Org buffer 中：
(org-typst-math-mode 1)
(org-fragtog-plus-mode 1)
(org-typst-preview) ; 可选：立即预览整个 buffer
#+end_src

光标进入公式时显示源码，离开时恢复图片，必要时请求新的 SVG。
=org-fragtog-plus-delay= 设置显示源码前的空闲秒数（默认 0）；
图片缩放使用 =org-typst-math-preview-scale=。编辑过的图片立即失效；
不使用 org-fragtog-plus 时仍可手动预览。关闭自动切换时清除对应 backend 的预览和待处理工作。

** 扩展 backend

=org-fragtog-plus-backend= 是 buffer-local 函数，接受 ACTION 和可选 FRAGMENT。
使用 =org-fragtog-plus-set-backend= 切换已启用 buffer 的 backend，它会先清理旧状态。

| ACTION   | 行为 |
| fragment | 返回光标处的 Org element，没有则 nil；不包含片段后的空白 |
| show     | 显示 FRAGMENT 的预览，重复调用不应反向切换 |
| hide     | 显示 FRAGMENT 的源码，重复调用不应反向切换 |
| clear    | 清理当前 buffer 的预览，使未完成结果失效 |

异步 backend 安装结果时应保留光标所在公式的源码显示。Typst adapter 继续使用已有
SVG 批处理、缓存与 diagnostics；org-fragtog-plus 自身无需了解 Rust 或 Typst。
